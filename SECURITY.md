# Reporting security issues

Do not put credentials, private context, exploit details for a live deployment,
or other sensitive material in a public issue.

If GitHub private vulnerability reporting is enabled, use the repository's
Security tab to submit a private report. Otherwise contact a repository
maintainer through an existing private channel and ask for a secure reporting
route. A dedicated contact and response policy must be configured before public
deployment; neither exists in this scaffold.

Include the affected revision, affected component, reproduction steps, and
observed impact. Use synthetic accounts and redact secrets.

No releases are supported yet. See [the security model](docs/security.md) for
implementation requirements and [release readiness](docs/release.md) for the
pre-publication checklist.
