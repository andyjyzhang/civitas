# 0002: Deep Agents publishing participant and product surfaces

Date: 2026-11-14

Status: accepted direction; implementation pending.

## Context

The team prioritizes a track prize, especially LangChain, while preserving the
provider-independent relay. The user also explicitly requested website and desktop
experiences with GitHub downloads at lower priority.

## Decision

Add a TypeScript Deep Agents change analyst as a network participant. Its visible
investigation uses a plan, virtual evidence files, specialized contract/impact
delegation, and a human-reviewed publication through Civitas MCP. Independent
Claude Code/Codex agents consume the event. They are not the analyst's subagents.

Use a synthetic property-maintenance API change as the shared demonstration for
enterprise, practical-AI, and possible built-world judging. Validate relevance
with real people; do not invent customer evidence. See [strategy](../track-strategy.md).

The product has a website and desktop companion. Keep CLI/MCP and HTTP client
logic shared beneath desktop. Build the web/relay proof first, then minimal desktop
UI. Versioned GitHub downloadable releases are lower priority. Framework and
platform support remain undecided. See [surfaces](../product-surfaces.md).

## Alternatives and consequences

A token LangChain import would not demonstrate useful Deep Agents behavior.
Replacing all coding agents with one central swarm would weaken the cross-owner
product claim. A participant at the publishing edge preserves that distinction
while giving the SDK meaningful investigative work.

The analyst adds model cost, latency, nondeterminism, and approval/checkpoint
complexity. Bound inputs and tool budgets; ground output in source revisions;
rehearse on fixed fixtures. A desktop app adds packaging work, so protect the core
proof with explicit cut lines. Prize eligibility still needs sponsor confirmation.
